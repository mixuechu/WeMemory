## 5. 综合评估

### 配置1-保守的优势
1. ✅ 捕获家庭关系（10个）
2. ✅ 更多边缘人物（16 vs 15）
3. ✅ 更多PARTICIPATED_IN关系（182 vs 130）

### 配置1-保守的劣势
1. ❌ 效率低（慢3倍）
2. ❌ Events碎片化（111个，质量低）
3. ❌ 成本高（22次API调用）

### 配置2-中等的优势
1. ✅ **效率高**（快3倍）
2. ✅ **Events质量高**（66个有意义事件）
3. ✅ 成本低（14次API调用）
4. ✅ KNOWS关系更多（50 vs 46）

### 配置2-中等的劣势
1. ❌ **遗漏家庭关系**（0 vs 10）⚠️
2. ❌ 少1个边缘人物
3. ❌ PARTICIPATED_IN关系少（但这是因为Events少）

## 6. 最终建议

### 问题核心
- **配置1**：高召回率，低精准度（捕获所有，包括噪音）
- **配置2**：高精准度，中等召回率（只捕获有意义的，遗漏家庭关系）

### 解决方案：折中配置

**推荐：配置2.5-优化中等**

```python
TIME_GAP_MINUTES = 45      # 45分钟（比60分钟更细）
MIN_MESSAGES = 8           # 最少8条（比10稍松）
MAX_MESSAGES = 150         # 最多150条（比200更细）
PARALLEL_WORKERS = 10      # 10并行
```

**预期效果：**
- 批次数：约18批（介于22和14之间）
- 耗时：约90秒（介于163和55之间）
- Events：约85个（捕获更多，质量仍高）
- 家庭关系：应该能捕获（因为更细粒度）

### 或者：Prompt优化

保持配置2，但在Prompt中**明确要求提取家庭关系**：

```
**关系提取重点**：
1. 人际关系：KNOWS
2. **家庭关系：HAS_SPOUSE, HAS_CHILD, HAS_PARENT, HAS_SIBLING（必须提取）**
3. 工作关系：WORKS_AT
4. Event参与：PARTICIPATED_IN
5. 讨论关系：DISCUSSED_WITH
```
