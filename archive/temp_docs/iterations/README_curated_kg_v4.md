# 精简版知识图谱 v4 - 亲属关系优化版

生成时间: 2026-03-06

## 🎯 v4的主要优化

将"xx的yy"（亲属/关系）类型的实体合并到主实体，进一步优化实体数量。

### 优化策略

1. **识别亲属实体**: 匹配"xx的yy"模式的实体（妈妈、爸爸、老婆、朋友等）
2. **合并到主实体**: 将"xx的yy"的所有数据合并到"xx"
   - 事件 → 转移到"xx"
   - 关系 → 转移到"xx"
   - 别名 → "xx的yy"成为"xx"的别名之一
3. **删除亲属实体**: 删除独立的"xx的yy"实体

### 示例

**优化前 (v3)**:
```json
{
  "米雪川": {
    "events": [事件1, 事件2],
    "all_aliases": ["米雪川", "雪川"]
  },
  "米雪川的妻子": {
    "events": [事件3, 事件4, 事件5],
    "all_aliases": ["米雪川的妻子", "萌萌", "老婆"]
  }
}
```

**优化后 (v4)**:
```json
{
  "米雪川": {
    "events": [事件1, 事件2, 事件3, 事件4, 事件5],
    "all_aliases": ["米雪川", "雪川", "米雪川的妻子", "萌萌", "老婆"]
  }
}
```

## 🎯 为什么这样优化？

### 理由1: 语义合理性
"米雪川的妻子"的事件，本质上也是与"米雪川"相关的事件。合并后更符合知识图谱的语义。

### 理由2: 查询便利性
用户问"米雪川最近在做什么？"时，应该能看到：
- 米雪川自己做的事
- 他妻子做的事（与他相关）
- 他家人做的事（与他相关）

### 理由3: 实体去重
许多对话中都会出现"米雪川的妻子"，但实际指的都是同一个人。合并后避免冗余。
